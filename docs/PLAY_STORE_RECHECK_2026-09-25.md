## Findings requiring resolution

1. **High: digital subscriptions purchased outside Play Billing.** `lib/src/features/wallet/seller_wallet_screen.dart:265` charges Sanaa Wallet for `seller_subscription`; `lib/src/features/ads/studio_entitlements.dart` uses subscriptions to remove watermarks. No Play Billing dependency is present. Integrate Billing with server verification, or make the Play distribution consumption-only and remove prohibited purchase steering. Applicable country/program exceptions must be established before relying on them. Physical-goods POS payments are a separate category. [Payments policy](https://support.google.com/googleplay/android-developer/answer/10281818).

2. **High: live privacy disclosure contradicts Terminal contact use.** Public `https://soko24.co/privacy-policy` fetched successfully today describes contacts as a social-discovery feature. `lib/src/features/settings/settings_screen.dart:194` describes uploading names, phone numbers and emails into the shop customer list across terminals. Correct the published policy for actual Terminal processing and reconcile Data safety declarations. Existing optional consent is useful but does not fix inaccurate policy text. [User Data policy](https://support.google.com/googleplay/android-developer/answer/10144311).

3. **High: no offensive-content report action in inspected native AI flows.** `lib/src/features/ads/ai_ads_tab.dart:324` invokes generation; `lib/src/features/marketing/marketing_generator_screen.dart:275` invokes marketing generation; backend `MarketingController.php:50` can invoke an LLM. No user report/moderation action was found in these feature directories. Add an in-app report control, persistent authenticated reporting endpoint and moderation handling for covered generative modes. Verify enabled modes/feature flags; template-only composition is not by itself generative AI. [AI policy](https://support.google.com/googleplay/android-developer/answer/13985936).

4. **Deletion fulfillment remains unverified.** Settings links to the working public `/account/delete-request` form. `apps/backend-laravel/app/Http/Controllers/ContactController.php:68` queues email and records a Contact request; this proves intake, not fulfillment. The page gives no clear expected completion time or Terminal-specific deletion/retention scope. Document those details and verify a disposable-account deletion through completion, including associated data and service providers. Manual processing and an external form are allowed; their existence is not itself a violation. [Deletion requirements](https://support.google.com/googleplay/android-developer/answer/13327111).

## Easily missed technical and Console checks

- Existing merged release manifest is API 36, min SDK 24, version 2032; this meets the currently published target API requirement. Gradle inherits target SDK from Flutter, so verify the final CI-built artifact too. [Target API requirement](https://support.google.com/googleplay/android-developer/answer/11926878).
- Broad photo/video, advertising-ID, SMS and background-location permissions were absent from the inspected merged manifest. `READ_CONTACTS` remains. Google is prompting contacts declarations from September 2026, but mandatory enforcement described in the current policy is January 27, 2027 for API 37+; do not incorrectly call this an immediate API 36 blocker. CRM is a listed use case, with justification still required when applicable. [Contacts timeline](https://support.google.com/googleplay/android-developer/answer/16935362).
- Merged manifest still includes `GeolocatorLocationService` with location foreground-service type but lacks `FOREGROUND_SERVICE_LOCATION`. Establish whether it can run; remove unused service or configure required permission/runtime behavior if needed. This is a runtime/configuration concern, not a proven upload rejection.
- Exported `AmaraBridgeProvider` protects identity assertions by caller package name only, without checking its signing certificate. Harden publisher verification. Public metadata is intentional; this audit does not claim an exploited leak or confirmed Play rejection.
- AAB dated September 15 and APK dated September 18 cannot certify today's dirty source. Current dependency list includes FFmpeg native code. Recheck all packaged 64-bit libraries, ELF/ZIP alignment and runtime on a 16 KB device for the exact new artifact; older audit results cannot establish this. [16 KB guidance](https://developer.android.com/guide/practices/page-sizes).
- Console-only unknowns: version code unused and higher than uploaded releases, correct upload signer, Data safety/financial declarations, reviewer login access, country distribution, listing accuracy, account verification and any testing gates. No evidence was available to mark these passed or failed.
